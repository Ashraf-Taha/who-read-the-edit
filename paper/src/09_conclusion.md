## 9. Conclusion

When the middle of a live context changes, the error of reusing the stale suffix does not spread evenly. It travels through the tokens that read the changed content and are then read by whatever comes next, which is why the same question, asked before or after the same deletion, sees errors several times apart. A cache can find these tokens cheaply because the suffix was encoded with the edited content present: prefill has already measured how much each token read of it, and one pass of the next input shows which tokens that input reads. Fusing the two rankings removed {{robust_exp.rrf.range_qa}} of the error in {{robust_exp.rrf.count_qa}} experiments outside the agent transcripts, and, {{robust_exp.rrf.not_behind_phrase}}, no role-free policy did significantly better. Either signal alone, and every fixed window, fell far behind somewhere. {{e21.conclusion}} Recomputing a cached question whole is the better choice when the suffix is short and the engine knows where the question is.

Positions are the easy part. Moving cached state needs no writes, and leaving gaps where content was deleted is an approximation of its own. A repair serves the next answer, and a state model that tracks exactness per segment lets an engine serve that answer now and return to the exact state later. The most useful next step is to test these signals in a serving engine at larger scale, against the region refresh of recent work.
